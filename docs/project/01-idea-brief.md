# coopera — 아이디어 브리프

> 입력 문서: [00-research.md](00-research.md) (문제·시장 조사), [00-harness.md](00-harness.md) (아키텍처 v2.2). 이 브리프는 두 문서의 결론을 슬롯에 매핑한 것이며, 상세 근거는 원문 참조.

## 한 줄 정의
<!-- 에코 테스트 통과 후 확정 -->
① 여러 개발자가 각자 AI 코딩 도구를 쓰면 각자의 의도·결정·학습이 AI 세션 안에 갇혀 증발하고, 팀은 중복 작업·의미 충돌·규약 표류를 겪는다. ② coopera는 Claude Code·Codex·Antigravity 등 AI 코딩 도구에 설치하는 하네스로, 이 맥락을 자동 캡처·통합해(LLM 위키 = 공유 이해의 정본 + push 기반 작업 트래킹 = 상호 인지) **모든 팀원의 LLM이 같은 프로젝트 이해를 염두에 두고 정합하게 개발**하게 만든다 — 작업 인수인계가 아니라 이해의 통합. ③ 자동 캡처×팀 공유×크로스툴×작업 시작 전 참고의 교집합은 현재 시장에 존재하지 않는다.

## 문제 정의

- AI 코딩 도구 도입으로 개발 맥락의 제3 저장소(AI 세션)가 생겼다: 프롬프트, 계획, 기각된 시도, 에이전트가 파악한 코드베이스 지식. **이 저장소는 세션 종료와 함께 증발하고 팀 누구와도 공유되지 않는다.**
- AI가 협업 문제를 증폭시키는 6가지: 속도 증폭(맥락이 더 빨리 낡음), 맥락 비대칭(의미적으로 충돌하는 코드), 결정 불투명, 중복 탐색, 규약 표류, 보이지 않는 WIP. (상세: 00-research §1.3)
- 정량 근거: CooperBench — 에이전트 협업 시 성공률 ~30% 하락(Stanford+SAP, 2026-01); AgenticFlict — 에이전트 PR 142k건 중 27.7% 머지 컨플릭트; Cursor의 auto-Memories 철회(리뷰 없는 학습 컨텍스트 불신); Claude Code 팀 메모리/세션 공유 FR 다수 오픈.
- 근거(본인): 내부 사용이 1차 목적 — 사용자 본인의 작업 환경이 곧 타겟. 구체 사례 기록은 공개 단계 전 보강(비차단).

## 타겟 사용자

- (아키텍처 문서의 가설) **2~10인 개발팀** — 병렬 AI 사용과 머지 고통이 가장 격렬한데, 엔터프라이즈 컨텍스트 엔진(sales-led, 50석+)은 닿지 않고 성숙한 OSS도 없는 공백 구간.
- 도구: Claude Code 우선(훅·MCP·플러그인 네이티브, 미충족 FR 수요, 한국 시장 채택 강세 — 토스·당근·컬리), 이후 Cursor·Codex 확장.
- 지금의 대안: git에 커밋한 마크다운(CLAUDE.md/AGENTS.md)이 사실상 전부 — 수동 유지, 사후적, "쓰는 사람만 씀".
- **첫 사용자(확정, 2026-07-28)**: 사용자 본인 — 로컬에서 Claude Code·Codex·Antigravity를 각각 사용하는 **1인 멀티툴 도그푸딩**(부분 도입 설계 덕에 1인 검증 성립). 검증 통과 후 전체 공개.

## MVP 범위

(00-harness §5 — 구현 순서만, 기간 없음)

### 포함
- **단계 1 — LLM 위키**: `wiki/`(concepts/modules/decisions/playbooks) + frontmatter(anchors·triggers·last_verified) + 페이지 린트 + CLAUDE.md/AGENTS.md 컴파일 + SessionEnd 증류기(고정 스키마 다이제스트 → 위키 diff 코드 PR 동승)
- **단계 2 — presence + 엔진**: `coopera` CLI(내부 엔진 — 사용자 노출 없음) + 푸시된 활성 브랜치 요약 + 세션 단위 git refs 발행/조회(서버 0대) + 캐시 물질화 + SessionStart/UserPromptSubmit 훅(주입 하드 예산 ~1.5k토큰) + 주입 가시화(systemMessage/statusline)
- **단계 3 — 마감**: PreToolUse advisory(로컬 캐시 대조), staleness CI, 주입 계측, Cursor/Codex 어댑터, MCP 래퍼(선택)

### 명시적 제외 (다음 버전 후보)
- 경량 허브 서버(실시간 세션 중간 갱신) — 승격 트리거 충족 시에만
- 충돌 레이더·소프트 클레임·asyncRewake·Channels
- 멀티 리포/조직 지식, 임베딩 검색, wiki bootstrap(콜드 스타트 시딩 — 백로그 상위)

### MVP 성립선 (확정, 2026-07-28)
- **정의된 설계 전체가 검증 대상** — "정의한 것들이 제대로 돌아가는 것"이 목적이므로 위키+presence(단계 1+2)가 최소선, 단계 3(어댑터·advisory)까지가 공개 전 완성선.

## 성공 기준

(2026-07-28 확정 — 목적: 내부 사용 → 향후 공개)

1. **작동 검증 (1차)** — 본인 로컬에서 Claude Code·Codex·Antigravity 각각으로:
   - 세션 시작 시 팀 활동·위키 요약이 주입되고 1줄 가시화가 보인다
   - 세션 종료(또는 소급) 증류가 고정 스키마 다이제스트와 위키 diff를 만든다
   - push 후 **다른 도구**의 새 세션이 그 결정을 반영해 계획을 세운다 (데모 시나리오)
