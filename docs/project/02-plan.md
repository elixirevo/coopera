# coopera — 기획서

## 개요

coopera는 Claude Code·Codex·Antigravity 등 AI 코딩 도구에 설치하는 **하네스**다. 여러 개발자가 각자 AI 도구로 같은 프로젝트를 개발할 때, 각자의 의도·결정·학습을 자동 캡처·통합해 **모든 팀원의 LLM이 같은 프로젝트 이해 위에서 정합하게 작업**하게 만든다(작업 인수인계가 아니라 이해의 통합 — [01-idea-brief](01-idea-brief.md) 참조). 구조는 2속도: LLM 위키(`wiki/`, 공유 이해의 정본, PR로 승격)와 push 기반 작업 트래킹(presence refs + 활성 브랜치), 이를 훅이 각 세션에 자동 주입한다. 서버 0대, git이 유일한 데이터 소스. 우선 제작자 본인의 로컬 멀티툴 도그푸딩으로 검증하고, 통과하면 전체 공개한다.

## 배경과 문제

문제 정의·정량 근거·시장 공백은 [00-research.md](00-research.md), 아키텍처 결정 전체는 [00-harness.md](00-harness.md)에 확정돼 있다. 핵심만: AI 세션이라는 제3의 맥락 저장소가 생겼는데 이를 팀으로 흘려보내는 파이프라인이 없고, "자동 캡처 × 팀 공유 × 크로스툴 × 작업 시작 전 참고"의 교집합은 시장에 부재한다(40+ 프로젝트 조사, 2026-07-27 검증).

추가된 최신 근거: **스파이크 4건 전부 통과**([00-spikes.md](00-spikes.md), 2026-07-28) — 커스텀 ref push, 주입 순응도(최약체 모델에서도 계획 조정 확인), Codex 훅 실발화, Antigravity 폴백 성립. 가장 위험했던 가정들이 이미 제거된 상태에서 시작한다.

## 목표와 성공 지표

브리프의 성공 기준 3단을 판정 시점과 함께 승계:

| 단계 | 지표 | 판정 시점 |
|---|---|---|
| 1차 작동 검증 | 로컬에서 Claude Code·Codex·Antigravity 각각: 세션 시작 주입+1줄 가시화 / 증류→다이제스트·위키 diff / push 후 **다른 도구** 세션이 결정을 반영해 계획 | M2 완료 시 (데모 시나리오) |
| 2차 정합성 검증 | 병렬 세션 2개가 같은 모듈에서 서로의 의도를 인지, 중복 구현·모순 결정 0건 | M3 완료 시 |
| 공개 전 기준 | 2인 이상 실제 팀에서 의미 충돌·중복 구현·규약 표류 감소 정성 확인 | 공개 판단 시 |

## 타겟과 가치 제안

- **첫 사용자**: 제작자 본인(1인 멀티툴 도그푸딩 — 부분 도입 설계로 1인 검증 성립). **공개 후 타겟**: 2~10인 개발팀(엔터프라이즈 엔진과 성숙 OSS 사이의 공백 구간).
- **핵심 시나리오 (push 축)**: A가 세션에서 결정 → push 순간 맥락(브랜치·의도·위키 diff) 공개 → B가 도구를 켜면 그 이해가 주입된 채 시작 → 겹침은 계획 단계에서 조정 → PR 머지로 위키 승격 → 이후 모든 에이전트가 같은 결정을 알고 부팅.
- 사용자 여정의 원칙: 개발자의 명시적 행동 0개(설치 1회·PR 리뷰 제외), 주입 내용은 항상 1줄로 가시화.

## 시장·경쟁 포지셔닝

경쟁 지형·비교표는 [01-idea-brief '가치 제안과 차별화'](01-idea-brief.md)와 [00-research §3](00-research.md)에 확정(2026-07-27 웹 검증, 재조사 불필요). 포지셔닝 문장: **"별도 서비스가 아니라 이미 쓰는 AI 코딩 도구에 심는, git만으로 동작하는 팀 이해 동기화 하네스."** 진입 각도: 내부 완성 → OSS 공개(무료 코어) → BM은 공개 단계에서 재론. 타이밍 리스크(플랫폼 흡수)가 있으므로 문서보다 구현·검증을 우선한다.

## 범위

브리프의 MVP 포함/제외를 승계하고 마일스톤에 배분(아래 로드맵). 제외 유지: 허브 서버, 충돌 레이더·소프트 클레임, 멀티 리포, 임베딩 검색. MVP 성립선 = 위키+presence(단계 1+2), 공개 전 완성선 = 단계 3.

## 로드맵 (마일스톤 기반 — 순서만, 기간 없음)

| 마일스톤 | 내용 | 완성 기준 (체크 가능) | 검증할 가정 |
|---|---|---|---|
| **M1 — 지식 루프 1회전** (리스크 킬러) | Rust 엔진 골격 + `wiki/` 스캐폴드·린트 + Claude Code 훅(SessionStart 주입·SessionEnd 증류) + coopera 리포 자체에서 self-hosting 시작 | 실제 Claude Code 세션 1개가 끝나면 **위키 diff가 자동 생성**되고, 다음 세션 시작 시 그 내용이 **주입되어 1줄 가시화**된다 (사람 개입: PR 리뷰만) | 남은 최대 리스크 — **자동 증류의 품질**(쓸만한 위키 초안이 나오는가) + 훅 경유 실세션 주입 작동 |
| **M2 — push 축 + 크로스툴** | presence refs(세션 단위) 발행/fetch/캐시 + 활성 브랜치 요약 + UserPromptSubmit intent 갱신 + Codex 어댑터(훅) + Antigravity 읽기(AGENTS.md 컴파일) | **데모 시나리오 통과** = 성공 지표 1차: Claude Code 세션의 결정이 push 후 Codex 세션 계획에 반영되고, Antigravity가 AGENTS.md로 같은 이해를 읽는다 | 크로스툴 왕복이 실제로 성립하는가, Codex PreToolUse가 apply_patch에도 발화하는가 |
| **M3 — 마감과 정합성** | PreToolUse advisory(캐시 대조) + staleness CI + 주입 계측 + 소급 증류(크래시·Antigravity 폴백) + 골든 세트 회귀 평가 | **성공 지표 2차 통과**: 병렬 세션 2개 정합성 검증. 계측 리포트 1회 산출 | 오염 방지 규율(예산·린트)이 실사용에서 유지되는가 |
| **M4 — 공개 준비** (공개 판단 후) | README·온보딩 문서(영어), 훅 승인 UX 정리, 플러그인 패키징, 라이선스 결정 | 외부 팀이 문서만 보고 설치 성공 | 협업 유의미성(2인+ 팀) — 공개 전 기준 |

## 리소스와 제약

- 구현 주체: Claude(한 번에 구현). 사용자는 결정·리뷰·도그푸딩 담당. 주당 시간 계획 불필요.
- 예산: 별도 없음 — 증류·주입은 각자의 기존 AI 도구 구독으로 동작(자체 API 키 없음, 확정).
- 외부 시간 제약: 없음. 단 플랫폼 흡수 리스크상 **빠른 검증이 전략적으로 유리**.
- 표기 규약: 모든 계획은 순서(단계)만, 기간·주차 금지 (사용자 지시).
