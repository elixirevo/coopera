intent: Implement Codex rollout distillation: add a Codex-schema extractor in coopera-core, extend scan_undistilled to cover ~/.codex/sessions/, and add unit tests + retro e2e coverage.
decisions:
- response_item lines are canonical in Codex rollouts; event_msg lines are streaming duplicates of the same messages and must be skipped — otherwise every message is counted twice in the digest.
- The Codex head sniff for the distiller-marker check uses 128 KB (vs 16 KB for Claude transcripts) because the session_meta first line alone embeds base instructions and runs 12–44 KB, making a 16 KB head unreliable for format detection or marker presence.
learnings:
- Codex injects system context as role:user packets — <environment_context>, <turn_aborted>, and plain-text AGENTS.md dumps (no XML wrapper) — so the extractor must filter these by prefix to avoid polluting the message list.
- Codex apply_patch envelopes appear as custom_tool_call lines (not tool_use); paths inside are relative to the session cwd recorded in session_meta, which can be a repo subdirectory rather than the repo root.
- The Codex session store (~/.codex/sessions/YYYY/MM/DD/) is not repo-keyed, so matching rollouts to the current repo requires parsing the session_meta first line and comparing payload.cwd against the repo root.
- Across 318 real Codex rollouts spanning cli 0.104 to 0.146, the response_item/event_msg split and session_meta shape are consistent — the schema is stable for this extractor.
