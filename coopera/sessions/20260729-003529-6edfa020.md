# Session digest — 6edfa020-7b7c-49e6-8c82-71abaac7b411 (claude-code)
author: Elixir · 2026-07-29T00:35:29.474437Z
intent: Design and implement coopera, a team-context harness for AI coding tools, from problem research through Rust implementation, achieving self-hosting and M1 verification
decisions:
- 2-speed architecture: git-backed LLM wiki (slow lane, review-gated) + presence via custom git refs (fast lane, fetch-at-session-start). Reason: wiki needs human review to earn trust; presence needs SessionStart visibility; git refs per-user eliminate merge conflicts entirely.
- Rust + git as sole data source, no servers. Reason: hooks budget <100ms so runtime startup matters; git is trusted by all developers; enables self-hosting from day 1; distillation cost attributed to each developer's subscription.
- Each AI agent (Claude Code, Codex, Antigravity, future tools) performs own distillation via configured command (default: claude -p). Reason: no shared API key needed; lowers adoption friction; tool-specific fallbacks handle those without SessionEnd hook.
- Context injection uses 3-stage progressive disclosure with hard ~1.5k token budget: L0 always (summary), L1 on anchor match, L2 explicit pull. Stale pages excluded automatically via last_verified commit check. Reason: prevents context rot and obsolete knowledge damage; models respond strongly to injected team context (empirically verified); stale awareness is automatic, not manual burden.
- Wiki landing is code-PR-centric: distilled initial drafts stage on working branch, land with code review, not separate PR. Reason: avoids review-fatigue spiral; keeps decision alongside its code change; treats wiki as team ledger, not session dump.
learnings:
- MCP subscriptions don't reach models in practice (clients don't consume them) — real-time coordination must use hook-time pull, not server push
- No existing harness combines git-backed + hooks-integrated + cross-tool + team-sharing; closest projects solve 1–2 pieces independently (Beads has 2-speed data, Entire has shadow branches, ACE-FCA has shared thoughts, but none combine all four)
- Per-session custom git refs (refs/coopera/presence/<user>/<session>) eliminate merge conflicts entirely via user-namespaced force-push safety
- Partial adoption has free read path: non-adopters still consume wiki via AGENTS.md compilation and pushed commits; adoption asymmetry is a feature, not a bug
- Presence of team context (activity map, decisions) measurably steers model behavior — test showed model shifted from conflict-plan to coordination-plan when context injected; absence led to Redis-lock reimplementation despite existing decision
- Distillation quality is production-viable: even haiku model extracted structurally sound decisions from transcript when given fixed schema, yielding review-ready wiki drafts
- Absence of surveillance (no time tracking, explicit opt-out) is load-bearing for presence-board trust — once visibility feels like monitoring, teams hide data
